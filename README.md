# cpp-calculator

Консольный калькулятор на C++20. Программа читает стартовое число, а затем
последовательно применяет операции и команды.

```
2 + 3 * 4 =
20
q
```

## Команды

| Команда      | Описание                                          |
|--------------|---------------------------------------------------|
| `+ <число>`  | Прибавить число к текущему значению               |
| `- <число>`  | Вычесть число из текущего значения                |
| `* <число>`  | Умножить текущее значение на число                |
| `/ <число>`  | Разделить текущее значение на число               |
| `** <число>` | Возвести текущее значение в степень               |
| `=`          | Вывести текущее значение                          |
| `c`          | Сбросить текущее значение в ноль (память не трогает) |
| `s`          | Сохранить текущее значение в память               |
| `l`          | Загрузить значение из памяти                      |
| `q`          | Завершить работу                                  |

## Сообщения об ошибках

Сообщения выводятся в `stderr`, после ошибки программа завершается с кодом 1.

| Сообщение                        | Причина                              |
|----------------------------------|--------------------------------------|
| `Error: Numeric operand expected` | Вместо числа введён другой токен     |
| `Error: Memory is empty`          | Команда `l` при пустой памяти        |
| `Error: Division by zero`         | Деление на ноль                      |
| `Error: Unknown token <токен>`    | Неизвестная команда или операция     |

## Сборка

### Visual Studio

Откройте `CppCalculator.slnx`. В солюшене два проекта:

- `CalculatorApp` — приложение;
- `CalculatorTests` — консольные тесты (папка `/tests/`).

Сборка: `Build → Build Solution`. Предупреждения включены на уровне `/W4`
и считаются ошибками.

Запуск тестов: правой кнопкой по `CalculatorTests` → `Set as Startup Project`,
затем `Ctrl+F5`. В консоли появится отчёт `35 passed, 0 failed`, а код возврата
процесса будет `0` при успехе и `1` при падении любого теста.

> Test Explorer не обнаруживает тесты самописного фреймворка: он поддерживает
> Microsoft C++ Test Framework, Google Test, Boost.Test и адаптеры вроде Catch2.
> Поэтому тесты здесь запускаются как обычный исполняемый файл. Если нужна
> нативная интеграция с Test Explorer, откройте папку проекта через
> `File → Open → Folder`: Visual Studio подхватит `CMakeLists.txt`,
> и тесты из CTest станут доступны в Test Explorer.

### CMake

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

Исполняемый файл: `build/Release/calculator.exe` в Windows
или `build/calculator` в Linux/macOS.

## Тесты

Тесты собираются CMake и запускаются через CTest:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCALCULATOR_WARNINGS_AS_ERRORS=ON
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Набор тестов покрывает:

- чтение чисел (`ReadNumber`);
- распознавание операций (`IsOperation`);
- вычисление операций (`ApplyOperation`);
- работу цикла калькулятора: арифметику, память, сброс, несколько выводов;
- все сообщения об ошибках и код возврата `RunCalculatorCycle()`;
- корректное завершение по `q` и по концу ввода.

## Структура проекта

```
calculator/
  calculator.h          — публичный интерфейс калькулятора
  calculator.cpp        — реализация операций и цикла
  main.cpp              — точка входа
tests/
  CalculatorTests.vcxproj  — проект тестов для Visual Studio
  test_framework.h         — минимальный тестовый фреймворк без зависимостей
  calculator_tests.cpp     — набор тестов
  test_main.cpp            — запуск тестов
CMakeLists.txt          — сборка приложения и тестов
```

## Правила оформления кода:

- Расставляйте правильные отступы.
- Давайте переменным информативные названия (без сокращений и транслита).
- Соблюдайте стиль именования переменных и функций.
- Не объявляйте несколько переменных в одной декларации.
- Между функциями оставляйте пустую строку.
- Фигурные скобки расставляйте так, как в примерах и авторских решениях, — { на строке с командой, } на отдельной строке.
- Не опускайте фигурные скобки.
- Избегайте магических чисел.

Стиль зафиксирован в `.clang-format` и `.editorconfig`.
